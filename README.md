# OSPOS 결제 및 포인트 정합성 QA 실험

오픈소스 POS [Open Source Point of Sale(OSPOS)](https://github.com/opensourcepos/opensourcepos)를 대상으로, 결제와 취소가 일어날 때 **재고, 기프트카드 잔액, 고객 포인트가 함께 맞게 움직이는지** 검증한 개인 QA 프로젝트다.

- 기간: 2026-10-27 ~ 2026-10-28
- 대상 버전: OSPOS 3.4.4-dev, commit `9253cfe8` (master)
- 환경: Windows, Docker Desktop(WSL2), PHP 8.2.35, MariaDB 10.5.29

## 왜 이 대상인가

매장 POS에서 결제를 취소하면 화면에는 '완료'가 뜬다. 하지만 손님의 기프트카드 잔액과 포인트까지 원래대로 돌아왔는지는 화면만으로 알 수 없다.
이를 직접 확인하려고 실제로 쓰이는 오픈소스 POS를 띄워 검증했다.

OSPOS는 판매, 복합 결제, 반품, 기프트카드, 고객 리워드, 재고 관리를 갖춘 POS이고, 2026년 10월에도 활발히 유지보수되고 있다.

현장과 개발 환경에서의 간극을 살펴보고 싶었고, 대표적인 오픈소스인 OSPOS로 이를 확인하고자 실험을 진행했다.

## 테스트 전략

**'돈과 잔액이 어긋나는 곳부터'** 검증했다. UI가 어색한 것은 불편으로 끝나지만, 취소 후 잔액이 돌아오지 않으면 매장과 손님이 금전 손해를 보기 때문이다.

1. **리스크 우선순위**: 금전·잔액·재고 불일치(P0) → 금액 계산 오류·설치 장애(P1) → 흐름·권한(P2) → 표시(P3)
2. **확인 항목 정리**: 결제·취소 때 함께 움직여야 하는 값(재고, 기프트카드 잔액, 포인트) 중 어긋날 수 있는 곳을 항목으로 정리하고, 우선순위가 높은 것부터 확인했다. 직접 확인한 항목은 3개이고 나머지는 이유와 함께 따로 적었다.
3. **화면과 DB 대조**: 결제 전, 결제 중간, 결제 후, 취소 후마다 DB 값을 기록해 기대값과 비교했다. 반복 조회는 [SQL 뷰](sql/qa_snapshot.sql) 하나로 묶었다.
4. **원인 좁히기**: 결함이 보이면 조건을 하나만 바꾼 비교 실험으로 원인을 특정했다.

가설별 근거와 테스트 케이스는 [test-plan.md](test-plan.md)에 있다.

### 1. 포인트 적립 실패 (회귀)

- 고객 메뉴로 만든 고객은 포인트가 0이 아닌 NULL로 저장된다.
- 적립 계산이 `points = points + 적립액`인데, NULL에 어떤 수를 더해도 NULL이라 잔액이 바뀌지 않는다.
- 적립 이력에는 2,000점이 기록되고 오류도 없으며, 화면은 `Points Available: 0`으로 표시해 문제가 가려진다.
- **포인트 초기값만 다른 고객 2명**으로 비교해 원인을 특정했다. (NULL 고객: 적립 안 됨 / 0 고객: 정상 적립)
- 원래 있던 'NULL이면 0으로 취급' 처리가 동시 결제 버그 수정(#4640)에서 빠지면서 생긴 회귀다.
- 수정 방향 3가지와 장단점, 피해야 할 방법, 회귀 테스트까지 제안했다.

### 2. 취소 시 잔액·포인트 미복원

- 기프트카드로 결제한 판매를 취소하면 **재고와 판매 상태는 돌아오지만** 기프트카드 잔액과 적립 포인트는 돌아오지 않는다.
- 20,000원 판매 2건을 취소한 뒤에도 기프트카드는 10,000원 그대로였다. (기대값 50,000원)
- 2021년 등록 후 아무도 재현하지 않던 이슈(#3216)를 최신 버전에서 DB 근거로 재현했다.

### 3. Docker 설치 실패

- 공식 안내대로 실행하면 `.env` 파일 쓰기에 실패해 컨테이너가 계속 재시작한다.
- 우회하면 이번에는 권한 문제로 실제 원인을 가리는 치명적 오류가 뜬다.

## 배운 것

- **화면은 결함을 가릴 수 있다.** 포인트는 화면에 0으로 보였지만 DB에는 빈 값이 있었다.
- **버그 수정이 새 버그를 만든다.** 수정된 기능뿐 아니라 그 주변의 데이터 조건까지 회귀 검증해야 한다.
- **결함을 단정하기 전에 확인한다.** 결제 중간 단계의 '잔액 30,000' 표시는 실제 차감이 아니었고, 결함이 아닌 안전 확인으로 기록했다.
